Floating-Point Addition: Align, Add, Normalise, Encode

Objective. Add two IEEE 754 single-precision words the way the hardware does - read the exponent fields, shift the smaller significand right by the difference, add the significands, check the normal form, then encode. The operands are X = 0x35C00000 and Y = 0x34A00000, the two words of GATE CSE 2026 Set 1 Q.26, so the animation and a verified previous-year question share one computation.
1.00x

Static explanation

Single precision is one sign bit, eight exponent bits and twenty-three fraction bits, always cut from the left of the 32-bit word. X = 0x35C00000 expands to 0011 0101 1100 ..., so its sign is 0, its exponent field is 0110 1011 = 107 and its fraction begins 1000. Y = 0x34A00000 has sign 0, exponent field 0110 1001 = 105 and fraction beginning 0100.

The stored exponent carries a bias of 127, so the exponents in the values are 107 - 127 = -20 and 105 - 127 = -22. Written in normal form, X = 1.1 x 2^-20 and Y = 1.01 x 2^-22. Two numbers can only be added when their binary points line up, so Y's significand is shifted right by the exponent difference of 2 and its exponent is raised to -20: 1.01 becomes 0.0101.

Adding the aligned significands gives 1.1000 + 0.0101 = 1.1101 at exponent -20. That lies in [1, 2), so it is already normal and neither the significand nor the exponent moves. The result's sign is 0, its exponent field is -20 + 127 = 107 = 0110 1011, and its fraction is 1101 followed by zeros, so the word is 0011 0101 1110 1000 0000 0000 0000 0000, that is 0x35E80000.

Read back, 1.1101 x 2^-20 is 1.8125 x 2^-20 = 1.7285e-6, which is 1.4305e-6 + 2.9802e-7 - exactly X plus Y. The check matters: a floating-point addition is right only when the encoded result decodes to the sum of the two values.

Common misconception

Three mistakes dominate. Shifting the larger significand instead of the smaller one, which raises the exponent that should have stayed put. Adding the significands and encoding the sum without the normal-form check, so a carry that reaches 2 is never shifted back. And believing that alignment is lossless: adding 1.0 to 2^-30 in single precision gives exactly 1.0, because the addend is shifted 30 places right, past all 24 stored bits, and rounds away entirely. That is why floating-point addition is not associative.

Quick check

Add 1.1 x 2^3 and 1.1 x 2^2 in the same format. What is the normalised result, and what has to happen to the exponent?

Answer

1.001 x 2^4. Align by shifting the smaller significand two places: 1.1 + 0.11 = 10.01 at exponent 3. That is 2.25 x 8 = 18, and it is not in [1, 2), so it shifts right once to 1.001 and the exponent increments to 4. Checking: 1.001 x 16 = 18.
