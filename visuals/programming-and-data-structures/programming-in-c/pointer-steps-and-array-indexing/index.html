Pointer Steps and Array Indexing

Objective. See why p + 1 moves four bytes and not one, why p2 - p1 counts elements while the addresses differ by more, and why a[i], *(a + i) and i[a] are three spellings of one object. These three facts decide most of GATE's C output questions.
1.00x

Static explanation

Take int a[5] = {10, 20, 30, 40, 50} with 4-byte ints, and suppose the array begins at byte address 2000. The five elements occupy bytes 2000 to 2019, four bytes each: a[0] is at 2000, a[1] at 2004, a[2] at 2008, a[3] at 2012 and a[4] at 2016. Nothing about the array is stored except those twenty bytes.

A pointer variable holds one address. Writing p = a copies the address 2000 into p, because in an expression the array name decays to a pointer to its first element. Then p + 1 is not 2001. The compiler multiplies the offset by the size of the type p points at, so p + 1 is 2000 + 1 x 4 = 2004, and *(p + 1) is a[1] = 20. This is the whole reason pointer arithmetic works with arrays of any element size: on a double array the same p + 1 would add 8.

The subscript operator is defined through that identity: a[i] means *(a + i). Because the addition of an integer and a pointer is commutative, i[a] means the same thing, so 2[a] is a[2] = 30. And subtracting two pointers of the same type counts elements: with p at a[3] and q at a[1], p - q is 2, even though 2012 - 2004 is 8. The result has type ptrdiff_t, and the subtraction is defined only when both pointers point into the same array or one past its end.

Two exceptions matter for exams. sizeof and unary & do not decay their operand, so sizeof(a) is the whole array (20 bytes here) while sizeof(a + 0) is the size of a pointer. And a function parameter declared int a[10] is adjusted to int *a, so inside the function sizeof(a) is again the pointer's size and the array's length is simply gone.

Common misconception

Reading p - q as a byte distance, or p + 1 as "the next byte". Both come from treating an address as a number rather than as a typed value. On this array, q - p between adjacent elements is 1 while the addresses differ by 4; on a double array it is still 1 while the addresses differ by 8. The compiler divides by sizeof(*p) for you, so the answer in elements never depends on the element size - which is exactly why GATE can ask the same question about ints and about doubles and get different-looking options.

Quick check

With int a[6] = {10,20,30,40,50,60} and int *p = a + 2, what are *(p + 3) - *p and p - a?

Answer

30 and 2. p points at a[2] = 30. *(p + 3) is *(a + 5) = a[5] = 60, so the difference is 60 - 30 = 30. And p - a subtracts two pointers into the same array, which counts elements: 2, not the 8 bytes between the addresses.
