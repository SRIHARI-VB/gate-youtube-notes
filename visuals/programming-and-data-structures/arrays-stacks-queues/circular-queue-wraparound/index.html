Circular Queue: Wraparound, Full and Empty

Objective. Watch five array slots serve as a queue of capacity four, see the rear index wrap past the end of the array, and see why the empty and full tests cannot both be front == rear. This is the setup of GATE CSE 2012 Q.35, whose answer is full: (REAR + 1) mod n == FRONT and empty: REAR == FRONT.
1.00x

Static explanation

A circular queue keeps the same array as a linear queue but lets both indices wrap: enqueue writes at rear and then sets rear = (rear + 1) mod n, dequeue reads at front and then sets front = (front + 1) mod n. Neither operation moves an element, so both are O(1), and slots freed at the front become reachable again instead of being lost.

The cost of using only two indices is that the empty state and the full state have to be told apart. In the convention used here, both indices start at 0 and rear is the index of the next free slot, so an empty queue has front == rear. If all n slots were usable, a queue holding n elements would also have front == rear, and the two states would be indistinguishable. The standard fix is to leave one slot permanently empty: the queue is full when (rear + 1) mod n == front, which fires one step before the indices meet, and the capacity becomes n - 1.

The number of stored elements follows from the same two indices: (rear - front + n) mod n. In the final frame of the animation, n = 5, front = 2 and rear = 1, giving (1 - 2 + 5) mod 5 = 4, and the live slots read 2, 3, 0, 1 - that is 30, 40, 50, 60 in queue order.

The other convention keeps an explicit count: empty when count == 0, full when count == n, and all n slots usable. A separate "full" flag does the same job. Any of these is correct; what is never correct is mixing the tests of one convention with the capacity of another, which is exactly what the distractors in the 2012 question do.

Worked example

An array of 5 slots, capacity 4. Enqueue 10, 20, 30, 40: rear walks 0 to 4 while front stays 0, and (4 + 1) mod 5 = 0 = front, so the queue is full with four elements. Dequeue twice: front becomes 2, and slots 0 and 1 are free. Enqueue 50: it is written at rear = 4 and rear wraps to 0. Enqueue 60: written at 0, rear becomes 1, and (1 + 1) mod 5 = 2 = front, so the queue is full again - now across the wrap, holding 30, 40, 50, 60.

Question variation

A circular queue is implemented in an array of size n with a separate count variable instead of a sacrificed slot. Initially front = rear = count = 0. After enqueue a, enqueue b, dequeue, enqueue c, what are front, rear and count, and is the queue full?

Answer

front = 1, rear = 3, count = 2, not full. The two enqueues write at 0 and 1 with rear = 2; the dequeue moves front to 1 and count to 1; the last enqueue writes at 2 and sets rear = 3 with count = 2. Under this convention the queue is full only when count == n, so all n slots are usable - the difference from the sacrificed-slot version is the capacity, not the wraparound.

Common misconception

That a circular queue of an array of size n stores n elements. In the two-index convention it stores n - 1, because one slot must stay empty to separate full from empty. A second misconception is that the full test is a test on the sum of the indices, or that front == rear can be checked as "full" - either swap makes the queue report the wrong state at exactly the moment it matters.

Quick check

In an array of size 8 under the sacrificed-slot convention, front = 6 and rear = 2. How many elements are stored, and which indices hold them?

Answer

4 elements, at indices 6, 7, 0 and 1. The count is (rear - front + n) mod n = (2 - 6 + 8) mod 8 = 4. Reading forward from front wraps past the end of the array, which is the same wraparound the animation shows at n = 5.
