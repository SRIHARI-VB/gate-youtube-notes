Call Stack: Descent and Unwinding

Objective. See why a recursion that prints after its recursive call reverses the input. Each call reads one character into its own local, the frames pile up, and the characters come out in the opposite order as the frames are popped. This is GATE CSE 2024 Set 1 Q.19, and the same mechanism produces the reversed digits of GATE CSE 2005 Q.31.
1.00x

Static explanation

The program is five lines long. fX declares a local a, reads one character into it, and if that character is not a newline it calls fX again. After the call returns, a second test prints a unless it is the newline.

On the input 1234 followed by a newline, five calls are made. The first reads '1', the second '2', the third '3', the fourth '4', and the fifth reads the newline. The fifth call fails both tests, so it returns without printing and its frame is popped. Now the fourth call resumes: its own a still holds '4', so it prints 4. Then the third prints 3, the second prints 2 and the first prints 1. The output is 4321.

Two facts do the work. First, each activation has its own a: the character is stored in the frame, not in one shared place, so every frame can print a different character on the way out. Second, statements after a recursive call run in the reverse order of the calls, because the deepest call returns first. Nothing about the function is clever; the order is entirely a consequence of where the putchar sits.

Move the putchar before the recursive call and the same five calls print 1234. That is exactly the pair of options the paper offers, and it is why the question is worth two lines of reasoning rather than a full trace.

Common misconception

That the printed order depends on how the recursion was written rather than on where the print statement sits. It depends only on the position: before the call gives the input order, after the call gives the reverse. A second misconception is that the newline call prints something - it prints nothing, which is why the program makes five calls but only four prints, and why the output is 4321 rather than something longer.

Quick check

In the same program, if putchar(a) were called before the recursive call, what would be printed for the input 1234?

Answer

1234. The first call reads '1' and prints it before recursing, so the characters come out in the order they were read. The recursion is identical - five calls, five frames - and only the position of the print has changed.
