Insert Climbs, Extract Sinks

Objective. One max-heap, six keys, two repairs. Watch an insert append the new key at the end and climb it past two parents, then watch an extract move the last key into the root and sink it past one child. The tree and the array are shown together, because a heap is one array and the tree is only a way of reading it.
1.00x

Static explanation

Both operations do the same two things in a different order: change the array at the end, then repair the order along one path. Insert appends the new key at index n+1, which keeps the tree complete, and then compares it with its parent, swapping upward while it wins. Extract takes the root, moves the last key into the root, shrinks the heap by one, and then compares downward, swapping with the larger child in a max-heap.

Each swap moves exactly one level, so each repair costs at most the height of the heap, which is floor(log2 n) for a complete tree. Here the heap has six keys, height 2, and the insert takes two swaps while the extract takes one. Nothing else in the tree is examined: every other parent-child edge was already valid and neither operation creates a new one.

The child chosen during a sink is not a free choice. The key must swap with the larger child in a max-heap, because the smaller child would then sit under a parent smaller than itself, and the heap would still be broken. The animation's fifth step shows the correct swap with 9 and not with 7.

Common misconception

That inserting means running heapify from the root. Heapify repairs a key that is too small for its children, and the inserted key is too large for its parent, so only a climb can fix it. On the array [10,8,5] with 9 appended, heapify from the root does nothing at all and the heap is left broken at the edge between index 2 and index 4.

Quick check

Insert 1 into the min-heap [2,5,3,9,7,4]. Which indices are compared, and what is the array afterwards?

Answer

[1,5,2,9,7,4,3], after comparing with index 3 (value 3) and then index 1 (value 2). Append at index 7: [2,5,3,9,7,4,1]. The parent is index 3, holding 3, and 1 < 3, so swap: [2,5,1,9,7,4,3]. The new parent is index 1, holding 2, and 1 < 2, so swap again: [1,5,2,9,7,4,3]. Two swaps, the height of a seven-key heap.
