Reversing a Singly Linked List: Three Pointers

Objective. Watch the list 1, 2, 3, 4 turn into 4, 3, 2, 1 with no new nodes and no array. Each step saves the next node, points the current node backwards, then moves the two pointers one place. Every node's link is written exactly once, which is why the cost is Theta(n) time and O(1) extra space - the claim GATE CSE 2022 Q.5 asks you to accept or reject.
1.00x

Static explanation

The loop is five lines and three pointers. next holds the node after the current one, curr is the node being processed and prev is the node already reversed. Each iteration does the same three things in the same order: save curr->next into next, set curr->next = prev, then move prev to curr and curr to next.

The order is not a style choice. curr->next is the only route to the rest of the list, so it must be copied out before it is overwritten. Write curr->next = prev first and the walk has nowhere to go: on a list of three or more nodes it returns to the node it came from and the loop never ends.

Four nodes need four writes and four iterations, one per node. That is the whole cost: the walk touches each node once, and the only extra memory is the two local pointers, which do not grow with n. So the time is Theta(n) and the space is O(1). The lower bound is also Theta(n) - every node's link must change, so nothing can be asymptotically faster - which is exactly why the 2022 option that claims n log n, and the option that claims it is impossible, are both wrong.

Watch where the NULL markers go. At the start NULL sits at the right end, after node 4. After the first iteration node 1 points at NULL and the marker appears at the left end instead. That left NULL is the new tail of the list, and when the loop stops prev holds node 4, the old tail, which is returned as the new head.

Common misconception

That reversal needs a second list, an array or a stack. It needs none of them: the nodes never move and no node is allocated or freed. A second misconception is that the recursive version satisfies an O(1)-space requirement - it is Theta(n) time like this one, but it holds one stack frame per node, so its auxiliary space is Theta(n), not O(1).

Quick check

The same loop runs on a list of 7 nodes. How many times is a next field written, and what does the function return?

Answer

7 writes, and it returns the old last node as the new head. The loop body runs once per node, and each run writes exactly one next field. When curr becomes NULL the loop stops with prev on the last node visited, which is the old tail - the head of the reversed list.
