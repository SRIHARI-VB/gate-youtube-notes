One Bit, Four Functions: the Slice, the Code and the Flags

Objective. Watch one bit slice of an ALU do four different jobs under one two-bit function code. The operand bits are A = 1 and B = 1, the carry in from the slice below is 1, and the code runs through 00 (AND), 01 (OR), 10 (ADD) and 11 (SUB). Only the code changes; the hardware never does.
1.00x

Static explanation

An n-bit ALU is n copies of one bit slice. Each slice holds a full adder, an AND gate and an OR gate, all fed by the same two operand bits, and an output multiplexer that decides which of those results leaves the slice. The carry is the only signal that crosses from one slice to the next, and it is chained through every slice in turn.

The multiplexer is driven by a function code. Two select bits name four codes, so this slice can be given four functions: 00 selects the AND gate, 01 the OR gate, 10 the adder, and 11 the adder again but with B inverted and the carry in held at 1, which is subtraction. Nothing new is built for subtraction - that is why the fourth function costs one mode bit and an inverter bank rather than a second adder.

With A = 1, B = 1 and the carry in set to 1, the four codes give: AND = 1, OR = 1, ADD = 1 with a carry out (since 1 + 1 + 1 = 3), and SUB = 0 with a carry out (since 1 + 0 + 1 = 2). The AND and the OR agree here, which is the point of the third step: one test case cannot tell two functions apart, and only the code says which one the ALU was asked for.

Each operation also leaves status bits. Z is 1 when every result bit is 0, N repeats the result's top bit, C is the carry out of the top slice, and V is the exclusive-or of the carry into and out of the sign column. Those bits, not the result, are what a conditional branch reads.

Common misconception

Two mistakes dominate. The first is treating the function code as an instruction number: it is not, because a load and an ADD can share the same ALU code - the load uses the adder to compute an address. The second is expecting the four codes to be four separate units; the fourth code reuses the adder, so subtraction's result arrives on the same output as addition's and takes just as long.

Quick check

The same slice is given A = 1 and B = 0, with no carry arriving from the slice below. What does each of the four codes produce?

Answer

AND = 0, OR = 1, ADD = 1 (no carry), SUB = 1 (with a carry, since 1 - 0 = 1). Working it out: the AND of 1 and 0 is 0; the OR is 1; the adder gives 1 + 0 + 0 = 1 with carry 0; subtraction inverts B and forces the carry in to 1 (that forced 1 is what turns the ones complement into the twos complement), so the adder computes 1 + 1 + 1 = 3, whose sum bit is 1 and carry out is 1 - and a carry out of 1 is exactly the "no borrow" signal that says 1 is not less than 0.
