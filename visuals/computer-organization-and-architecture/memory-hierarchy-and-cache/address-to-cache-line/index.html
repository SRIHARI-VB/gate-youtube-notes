One Address, Three Caches: Where Tag, Index and Offset Come From

Objective. Watch one 32-bit address, 0xA248, being taken apart by the same 2 KB cache built three ways - direct mapped, 4-way set associative and fully associative. The offset never moves, the index shrinks as the associativity rises, and every bit the index loses the tag gains. That is the whole of the mapping arithmetic, and it is why associativity changes both the tag width and the number of comparators.
1.00x

Static explanation

A cache of 2 KB of data with 64-byte blocks holds 32 lines. The block offset is log2 64 = 6 bits in every organisation, because it addresses a byte inside a 64-byte block. What changes is how the 32 lines are grouped. Grouped one line per set, there are 32 sets, so the index needs 5 bits and the tag keeps the other 21. Grouped four lines per set, there are 8 sets, the index needs 3 bits, and the tag grows to 23. Grouped as one set of 32 lines, there is no index at all and the tag is 26.

For the address 0xA248 = 1010 0010 0100 1000 in 16 bits, or 0000 0000 0000 0000 1010 0010 0100 1000 in the full 32, the low six bits are 001000, which is offset 8 in all three cases. In the direct-mapped cache the next five bits are 01001, so the block lands in line 9 with tag 20. In the 4-way cache the next three bits are 001, so it lands in set 1 with tag 81. Fully associative, the index is empty and the tag is 649.

The tag is not decoration: its width says how many memory blocks compete for one line. A 21-bit tag means 2^21 blocks share each direct-mapped line, so any two of them that differ by a multiple of 32 lines evict each other no matter how empty the rest of the cache is. Moving to 4-way cuts the competition by four and adds two bits of tag; going fully associative removes conflict misses altogether and costs 32 comparators.

Common misconception

The usual error is to keep the index at log2(lines) whatever the associativity, which gives a 5-bit index and a 21-bit tag for all three rows. In a set-associative cache the index names a set, not a line, so it is log2(sets) = log2(lines) - log2(ways). The second error is the mirror image: writing an index of log2(lines) for a fully associative cache, which has one set and therefore no index field at all - that is exactly the distractor in GATE CSE 2019 Q.1.

Quick check

The same 2 KB cache and the same 64 B blocks, but now 2-way set associative with a 32-bit address. What are the three field widths, and how wide is each comparator?

Answer

Tag 22, index 4, offset 6; comparators 22 bits wide, two of them per set. 32 lines in 2-way groups is 16 sets, so the index is 4 bits and the tag takes the two bits the index gave up: 21 + 1 = 22. The offset is still 6. Two ways means two comparators per set, and each must compare the full 22-bit tag.
